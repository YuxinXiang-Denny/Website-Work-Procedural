01

Introduction

Welcome to Marigold Tech!

As a Distributed Systems Engineer, you will design, maintain, and upgrade our distributed system, which handles billions of operations per minute and is built to serve more than one million customers at the same time. You will write code, review code, and revise and comment on code that others submit. Please strictly follow the development procedures in the Step-by-Step Guides.

Our workplace is fully inclusive:

  • Meetings. If you are not comfortable participating in our meetings in person, you are welcome to join remotely, or to sit a meeting out entirely.
  • Respect. If you experience any insult or discrimination based on your identity, please keep all evidence and report it; the person responsible will be dismissed immediately. In turn, we ask that you treat every colleague with the same respect.
  • Feedback. Feel free to email Supervisor Pica (pica@marigold.uiuc) about anything you think could be improved in our workplace. Every suggestion will be carefully considered.
02

Common Q&A

Can I use AI tools like ChatGPT, Copilot, or Google Gemini?
Yes and no. Claude Code is the only approved AI tool, because it is significantly more powerful than the alternatives. Claim your company account here. Make sure you understand and test everything it produces, and never share private data with it.
How do I request time off?
Submit a time-off request through the HR portal at any time.
How do I get promoted?
We hold performance reviews every quarter. Your contribution to company revenue is a key factor: the more value you create, the faster you can be promoted.
I have an idea for a new project. Can I act as an intrapreneur?
Yes! You can pitch your idea and apply for company funding.
Any other questions?
Email Supervisor Pica at pica@marigold.uiuc!

Step-by-Step Guides

What should you do if you…

Before you start Learn to use Git (a version control tool) and GitHub (a collaboration platform). These two short videos cover the basics.

3A

…want to submit code?

  1. 1
    Create a new branch. It must be separate from the main branch. Commit and push your code to this branch.
  2. 2
    Create a Pull Request (PR), and assign Supervisor Pica and the reviewer of the week as reviewers.
  3. 3
    Check the review result. 
    if pr.Approved() && pr.MergedInto("main") {
	goto Step4
} else {
	code.Revise(review.Comments)
	goto Step2
}
  4. 4
    Thank your reviewers, and enjoy your day!
3B

…are asked to review others’ submissions?

  1. 1
    Write unit tests (as detailed as possible) for the submission, based on the specification submitted with the code.
  2. 2
    Ask Supervisor Pica to review the tests you wrote.
  3. 3
    Check her feedback. 
    if pica.Approves(myTests) {
	goto Step4
} else {
	myTests.Revise(pica.Instructions)
	goto Step2
}
  4. 4
    Run your test cases on the submitted code.
  5. 5
    Check the test results. 
    if code.PassesAll(myTests) {
	pr.Approve() // on GitHub
	pr.MergeInto("main")
} else {
	pr.Comment(issues)
	pr.Decline()
	notify(pr.Author)
}
